# MFA implementation evidence — 2026-10-06

## Implemented

- TOTP enrollment uses an encrypted pending secret, a ten-minute expiry, and a password recheck before enrollment begins.
- Confirmation enables TOTP and returns ten recovery codes once. Recovery values are stored as hashes and consumed atomically.
- TOTP counters are consumed atomically to reject a reused time-window code.
- Regenerating recovery codes and disabling MFA require the password plus a valid authenticator or recovery code. MFA changes are audited and revoke other sessions.
- Login requests for MFA-enabled accounts return an MFA challenge and validate its factor before creating a session.
- Account security settings are available at `/settings/security`.
